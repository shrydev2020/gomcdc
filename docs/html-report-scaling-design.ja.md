# 大規模HTMLレポートの設計

カバレッジの概要から、対象のソースとテストの根拠へ辿れる静的レポートを生成する。ブラウザが一度に読み込む量は、1ページの容量と要素数で制御する。

## 原因

従来の単一HTMLは、全ファイルのソース、注釈、観測、MC/DCの根拠を初期ロード時に読み込んでいた。折りたたまれた要素もDOMとして常駐するため、観測数と注釈の重なりに応じてブラウザのメモリ使用量が増える。

対策は、詳細を独立した文書に分け、選択されたページへ通常のリンクで移動すること。初期表示では概要と各索引への入口を読み込む。[測定結果](html-report-scaling-results.ja.md)に同じ保存結果を使った比較を示す。

## ページ構成

| ページ | 表示内容と移動先 |
|---|---|
| 概要 | 11指標、実行結果、Findings件数、各索引へのリンク |
| package / file | 集計と下位対象へのリンク |
| function | statement・clause・decisionの根拠 |
| decision / condition | 判定結果、条件ごとの達成状況、witnessと観測表へのリンク |
| witness | 対象条件、A/Bの結果とtest、条件比較表、出所 |
| evaluations | 観測順の表。条件列、ID、status、結果、test/run/package/processを表示 |
| source | 元ソースの連続範囲、指標別の色、注釈一覧、元ファイルのダウンロード |
| Findings | 未達や確認を要する項目。指標・状態別の索引、ソースと根拠へのリンク |
| producers | 計測元のintegrity・completeness・mapping・usabilityと診断 |

witnessの観測値とcompletionは別の列で表示する。completionは解析で用いた値の割り当てを表す。全観測の順序、反復、出所を保持する。

## 読み込み量の上限

| 単位 | 上限 |
|---|---:|
| HTML文書全体 | escape後1 MiB、5,000要素 |
| 本文バッファ | 512 KiB、3,500要素 |
| 通常の索引 | 100項目 |
| 観測表 | 200行、16条件列 |
| ソースページ | 400断片。各断片は最大1,024 bytesか行末まで |
| 長文フィールド | 1,024 bytesを超える値を全文ページへ分割 |

本文を追加する前に容量と要素数を確認し、上限に達したらページを確定する。ヘッダーやナビゲーションを含む完成文書にも上限を適用する。長い文字列はプレビューと全文へのリンクとして表示する。

## 実装の責務

| 担当 | 入力と責務 |
|---|---|
| `htmlReportRenderer` | analysis.Resultと元ソースから、階層・根拠・Findingsの表示内容を組み立てる |
| `htmlPageWriter` / `htmlPageSeries` | ページの容量管理、長文の継続ページ、HTML/CSSと元ソースの書き出しを担当する |
| `walkHTMLColors` | 注釈の始点・終点を走査し、指標と状態ごとの有効件数から区間色を求める |
| `htmlGenerationDigest` | 生成ファイル、ページ上限、リンク先を検査し、ファイル名と内容からdigestを作る |
| `publishHTMLGeneration` / `publishHTMLEntry` | 完成した世代の配置と入口の置換を担当する |

共通CSSとページ外枠は専用テンプレートに置く。単一HTMLとディレクトリ出力は共通CSSを参照する。Findingsはfunctionごとに列挙し、その場で索引へ追加する。

色の走査に必要な領域は、注釈の境界イベントと固定数の状態カウンター。注釈詳細は専用索引に保持し、色付き断片から元の根拠へ移動できる。

## ソース参照とエラー

byte offsetを持つ範囲はその座標で解決する。行・列だけを持つ範囲は、同じ元ソース上のbyte位置へ変換する。不正な座標はmapping診断として表示する。ページ範囲やアンカーの内部不整合は生成エラーにする。

入力の重複ソースと欠けたDecision IDは生成時に報告する。ファイル操作のエラーには操作名と対象を付け、原因をラップして返す。呼び出し元は`errors.Is`でキャンセルやファイルシステムの原因を判定できる。

## 公開手順

1. 出力先に専用の一時ディレクトリを作る。
2. ページ、共通CSS、元ソースを書き出す。
3. 全ファイルの容量・要素数・リンク先を検査し、世代のdigestを求める。
4. `report-<digest>`へ配置する。同名の既存世代は内容を検証して再利用する。
5. 入口を一時ファイルへ書き、同期してから`index.html`を置換する。

失敗時は一時出力を片付け、原因を返す。旧世代を保持することで、開いているタブのリンクを維持する。

## 利用と検証

入口は`coverage-html/index.html`。HTMLとCSSで動作し、`file://`からオフラインで閲覧できる。配布には出力ディレクトリ全体を含める。検索と印刷の対象は現在のページ。ソース表示は各ページでStatementモードから始まる。

回帰テストは、ページ上限、観測の値と順序、witness、ソース復元、リンク、キャンセル、既存世代の再利用と破損を確認する。ブラウザ検証では、ソースの色、根拠への移動、DOM数、renderer RSS、ロード時間を測る。
